MCP Server for Xiaozhi

MCP server that dials out over WebSocket to a Xiaozhi endpoint, exposing HA's Assist LLM tools so Xiaozhi ESP32 voice assistants can read exposed states and control devices.

Notes

Reverses the usual MCP direction: HA keeps a persistent outbound WebSocket to the endpoint URL you paste, giving that remote service standing reach over everything exposed to Assist — the only credential is the token inside the URL. A fork of the core MCP Server, bounded by the same Assist entity exposure. Quiet since late 2025.

Is this wrong about MCP Server for Xiaozhi? That's the bug we care about most — open a correction. Maintainer reports get priority.
