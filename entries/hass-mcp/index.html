hass-mcp

Community MCP server that gives LLM clients (Claude Desktop, Cursor) access to Home Assistant via a long-lived access token.

Model Context Protocol container · external inference: local · cloud

What it can reach

  • reads statesCan read the live state of entities exposed to it — temperatures, lights, locks, presence.
  • reads historyCan query past states and events from the recorder, history, or logbook.source ↗
  • controls devicesCan call Home Assistant services to switch, dim, unlock, or otherwise act on devices.source ↗

Not granted: reads camera · microphone · creates automations · edits files · executes code · unattended

Notes

The trust model is the difference from the core MCP Server integration: this authenticates with a long-lived access token, so its reach is bounded by what that token can do — effectively your whole instance — rather than by Assist entity exposure. Its tools go beyond states and services: it can also edit dashboards and restart Home Assistant. Understand that boundary before wiring it to a cloud client.

Is this wrong about hass-mcp? That's the bug we care about most — open a correction. Maintainer reports get priority.
